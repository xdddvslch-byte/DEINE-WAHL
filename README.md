# DEINE WAHL — симулятор етичних дилем

**Команда:** KORDON X · **Завдання 1.** Симулятор етичних дилем (Ethical Dilemmas Simulator) · IV Хакатон з питань виховання доброчесності та запобігання корупції, BITEC 2026

![Обкладинка](docs/img/cover.jpg)

## 1. Проблема і користувач

Курсанти й офіцери знають норми доброчесності, але рідко відпрацьовують рішення **під тиском, у браку часу й у конфлікті лояльностей**. Тренінги на основі дилем потребують підготовленого ведучого й перевірених кейсів, тому проводяться рідко.

**Користувачі:** курсанти й слухачі ВВНЗ, молоді офіцери, слухачі курсів підвищення кваліфікації — для самостійного проходження. Викладачі доброчесності й уповноважені з питань запобігання корупції — як ведучі заняття й автори сценаріїв.

## 2. Що робить рішення

- **3 сценарії команди × 3 етапи × 18 маршрутів**, без очевидно правильного варіанта: конфлікт інтересів (S06), подарунок (S07), неформальний тиск керівника (S08). Кожен — за мотивами ситуацій Посібника CIDS (2025).
- **Бали за трьома вимірами** (доброчесність, ефективність, довіра) з поясненням «чому такі бали». Загального балу немає.
- **Наслідки «одразу» і «згодом».** Відкладені наслідки збираються в розборі.
- **Норми з дослівною цитатою, редакцією і статусом звірки** — 36 з переліку організаторів і 2 спеціальні для прикордонної служби (ст. 23 ЗУ «Про ДПСУ», ст. 23 ЗУ «Про прикордонний контроль»), додані за порадою ментора. На кроці 3 справи 01 — правова довідка: кому закон дозволяє перевагу в перетинанні кордону. Окремо показано, на кого норми поширюються.
- **Груповий режим:** ведучий показує сцену, аудиторія голосує анонімно, розподіл видно лише за командою ведучого. Після заняття видно, де група розійшлася найбільше.
- **Тиск часу** (опційно): 20 с на рішення. Якщо не встиг — рішення ухвалює «інерція». Перед вибором можна відкрити «Тест із 5 перевірок» Посібника CIDS.
- **Формат організаторів без змін.** Наші сценарії проходять їхній `zibraty.py`, а їхні приклади S01–S05 відтворюються в симуляторі. Викладач може завантажити свій JSON просто в застосунку. Є експорт у SCORM для Moodle.

## 4. Як запустити

Потрібно: сучасний браузер; для збірки — Node.js 18+.

1. Завантажте репозиторій (Code → Download ZIP) і розпакуйте.
2. Відкрийте `index.html` у браузері — працює офлайн.
3. Щоб JSON-сценарії читалися напряму без збірки: `npx --yes http-server -p 8080 .` → http://localhost:8080
4. Після зміни сценаріїв: `node tools/build.mjs` (перевірка → `data/bundle.js`, `docs/stsenarii.md`, `dist/strict/`).
5. Пакет для Moodle: `node tools/build.mjs --scorm` → `dist/deine-wahl-scorm12.zip`. Десктоп для Windows: `npm install && npm start`.

## 5. Як влаштовано

**Стек:** HTML, CSS, JavaScript без фреймворків і без сервера; опційно Electron.

| Компонент | Файл | Роль |
|---|---|---|
| Сценарії команди | `data/stsenarii/S06–S08.json` | Формат організаторів + необовʼязкове розширення `podacha` |
| Приклади організаторів | `data/pryklady/S01–S05.json` | Без змін; доводять сумісність формату |
| Перелік норм | `data/normy.json` | Перелік організаторів (36 норм) + 2 норми прикордонного законодавства: цитати, редакції, статус звірки |
| Схема | `data/schema/stsenarii.schema.json` | Схема організаторів + поле `podacha` (подача і правова довідка кроку) |
| Валідатор | `validate.js` | Ті самі перевірки, що в `zibraty.py`, плюс наші; спільний для збірки й імпорту |
| Рушій | `app.js` | Проходження графа, таймер, голосування, розбір |
| Збірка | `tools/build.mjs` | Перевірка, bundle, карта рішень, строгий експорт, SCORM |
| LMS | `scorm.js` | Передає в LMS лише статус «completed» |

**Правила, що ухвалюють висновки (явні, без ШІ):**

1. Бал за вимір = сума балів обраних варіантів (−2…+2 кожен), заданих автором сценарію з текстовим поясненням. Виміри не додаються між собою.
2. Наслідок «одразу» показується на наступному кроці, «згодом» — у розборі.
3. Тиск часу: коли вийшов час, спрацьовує варіант `podacha.inertsiia`; якщо його немає — варіант із найвищою ефективністю, за рівності — з найнижчою доброчесністю.
4. Груповий режим: перехід «за більшістю» — лише за явної більшості; за нічиєї вирішує ведучий.
5. Валідатор не пропускає сценарій команди з менш ніж трьома етапами й попереджає, якщо варіант кращий за інші за всіма вимірами.

Однакові вибори завжди дають однаковий розбір; для кожного бала видно, з яких рішень він складається.
